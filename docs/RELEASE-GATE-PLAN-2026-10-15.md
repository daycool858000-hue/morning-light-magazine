## 2. 決議的最小技術方向（尚待作者授權後實作）

新增一份簡單的 `content/release-approvals.json`（**初始核准名單為空**），與原有內容資料分離，不新增 CMS、後台、帳號或新路由。它只記錄作者是否同意公開某一批、核准日期、允許的 ID、可公開範圍與當時核准的內容摘要雜湊。作者一次核准一個批次，不須對每個 ID 打勾。

查核與發布維持三個獨立概念：

1. **來源查核**：保留 `review.by`、`review.date`、`review.source`、`review.scope`；新增簡單機器可判斷的 `review.level`，例如 `official-entry`、`hotline-purpose-hours`、`official-channel`、`incomplete`，不得用自由文字中的「已」字判定。
2. **原有人工確認狀態**：`status` 與 `checkedAt` 的原義不變，沒有人工逐頁驗證就保持 `待確認`／`null`；不把 AI 紀錄填作人工查核。
3. **作者發布決定**：只在獨立核准清單記錄發起人同意公開的批次、日期、類型及核准範圍，不代表發起人逐一查閱來源或法律專業認證。

正式版需同時滿足：ID 在已授權的明確名單、內容與授權時一致、對應的官方／機構原始來源查核資料完整、查核程度足以支持實際顯示欄位、`published !== false`（如適用），且 `status` 不是 `需要修正`／`已撤下`。任何一項不符合都不公開。未核准新增資料預設不公開。核准後如資料或圖片原檔／裁切設定實質改變，必須重新核准，不能沿用舊簽核；日期、核准者與摘要只記錄真實事件。

**注意：** 既有文章／活動的人工查核公開規則原封不動，僅為資源、專線、管道、圖片加入明確的新發布門檻。已人工查核資料也不得略過作者的公開設定。

## 4. 對外標示與最小修改清單

- `resourceCard`：核准的有限查核範圍顯示「官方入口已核對（AI 協助，YYYY-MM-DD）」以及實際核對範圍；不顯示矛盾的「待查核／最後人工查核：尚未查核」，也不冒稱服務條件已全面確認。可以保留連往來源的入口。

- `main`、Pages 開關、正式部署工作流程、既有首頁／分類數量、英文新名稱、授權方式均不得改變。

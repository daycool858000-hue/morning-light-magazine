## 需要如實保留的四項差異

1. **嘉義市**：第一張是可讀的**市政府首頁**，可沿「便民服務 → 社福救助 → 社會福利資訊網」找業務，網站當前不應將此卡標為「社會處獨立站已直接讀取」。另有衛福部**東、西區兩中心**的中央名錄作第二層查詢入口。
2. **高雄市**：目前可用[高雄市政府社會福利服務目錄](https://www.kcg.gov.tw/MainThemeDetail.aspx?eservicemaincategory=80&n=114AAE178CD95D4C&sms=02036FE10C1B5C8A)，官方頁明列婦女福利、托育、救助與單親特境等分類，**但不是社會局專屬官網首頁**。此次透過政府搜尋索引取得內容；仍須在手機實際打開目標 URL。
3. **嘉義縣及連江縣**：目前採**衛福部官方社福中心通訊錄**補足所在地的可用導航（分別 6、1 個中心）；中央中心名錄**不可冒稱地方社會局／民政社會處的主管機關官網**，也不可宣稱中心即時營業或全部扶助種類均受理。
4. **金門、澎湖、南投、新竹縣／市、宜蘭、臺東、高雄**：工具開啟頁面部分受阻，已取得同官方網址的政府頁搜尋內容。其餘頁面亦可能是快取，而非本次 HTTP 真實探測；**如發現真實 iPhone 打不開，須另找更穩定官方替代入口，不可以 AI 索引有內容就主張網頁一定正常**。

## 導入正式資料之前需交 Claude 的具體資料品質要求

- **原本的 16 筆已授權機構、專線、SMS、9 張圖片均不得被覆寫**。新 23 筆必須有獨立 ID、縣市 ID、AI 核對範圍和新的批次授權快照；`checkedAt` 不能虛填為作者人工查核。
- **分類與服務類型要反映用途**：18 張社會局處卡歸「地方主管機關（`social-affairs`）」；2 張市府替代入口清楚標為**市府福利目錄／導覽**，不能叫「社會局首頁」；3 張社福中心名錄是**服務中心列表**，不得塞到「婦女福利服務中心」類型（並非專門婦女中心），也不要冒充主管機關。現有分類尚無專屬「一般社福中心」主題，需讓 Claude 在不增改六大分類 UI 的前提下，選擇合適且誠實的現有主題或在卡片文字標明中心名錄，並驗證點擊後所在分類正確。
- **服務類型篩選的潛在體驗缺口**：目前 `city.js` 是直接比對 `serviceTypes`，若所有新卡僅填「社會福利」，使用者選「婦女福利」就可能看不到該縣市任何新卡。凡官方來源確實含婦女福利分類的局處或福利目錄，可一併標註現有的「婦女福利」，**但不可無證據把一般社福中心名錄標為婦女中心**。對各服務類型必須加入實際篩選測試，不能只測「縣市有卡」。
- **防止重複顯示**：同一機構即使出現在多個主題也應維持單一資料 ID；嘉義市兩張卡是不同用途，名稱、類型、說明要清楚。外部網址使用 HTTPS，來源與卡片 URL 一致。
- **發布門檻**：正式上稿前須先取得網站擁有人對確切 23 筆名稱／URL／基本說明的**內容發布核准**，不得挪用原 16 筆核准；真正合併 `main` 或部署 Pages 仍須另外明確同意。

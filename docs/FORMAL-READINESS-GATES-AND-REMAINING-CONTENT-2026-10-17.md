## 能否現在正式發布？分兩個維度

**工程完成程度：** PR #19 已通過最新整合與正式版模擬測試，PR #20 的實際 QA 同網址覆蓋保護已合併。現在可以進行正式版**發布前整合流程的最後一次確認**，但此時 `main` 仍非新44篇完整 release 分支，不能從舊版 main 直接部署。

**實際正式發布權限：** `content/launch-approvals.json` 的44篇與五組候選功能 SHA 紀錄尚未由真正發布決定填入。此前使用者已確認網站架構和文章內容，不等於 GitHub 技術系統已留下同批正式版本釋出紀錄。取得最終發布範圍授權後，可以採已核對版本**一次性版本登錄**，而不是重審44篇內容。**仍不可自行填入虛擬核准**。

**待加入的13篇：** 原稿來源與全文比對及57篇隔離建置已完成，**但公開 QA 閱讀版實機、7筆工具阻擋與3個JS官方頁的瀏覽器複驗、必要的法律／健康當期精確核對尚未全部完成**。因此應列「隔離QA測試合格、待最終連結／閱讀版驗收」，不能現在聲稱13篇已達完全正式發布門檻。

**54主題入口：** PR #18 的54組來源尚為 `ownerApproved:false` 獨立測試候選，不可因 PR #19 能模擬 production 渲染，就隨意推定54組每個新的原始URL都已獲站主逐條出版核准。應區分既有六大主題導航本身與新增54個各自外部來源。

## 實際剩餘清單（不讓 Claude 浪費額度重跑已完成項目）

1. **取得實際發布範圍**：以現有44篇與已驗收功能為第一批，釐清54新增入口及35新增資源是否合入同批；如果某候選尚缺實際確認，就維持原有頁面並在 release gate 中排除候選，不能用測試簽核代替。
2. **整合順序**：保留原公開 QA 備份和 PR #20 已合併的禁自動覆蓋規則；仔細安排 PR #18／#19 與 main 的實際合併順序，避免把舊main出版至同一 Pages URL。
3. **完成13篇必要瀏覽器 QA**：7個工具受阻連結、3個依賴JS的兩廳院頁、13篇 iPhone / WebKit 閱讀；不能因隔離HTML build綠燈就宣稱「全部外站實機驗收」。
